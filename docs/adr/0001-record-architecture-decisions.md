# 0001. Record architecture decisions

- Status: Accepted
- Date: 2026-10-14

## Context

Decisions made during development are easy to lose. A reviewer looking at the code can see
*what* was built but not *why*, or which alternatives were rejected.

## Decision

Record each significant decision as a short Markdown file in `docs/adr/`: context, decision,
consequences. Number them sequentially. Never edit an accepted record; supersede it.

## Consequences

Decisions get written down when they're made, which forces them to be justified. The cost is a
few minutes per decision.
