# Revisa

Reads the title blocks of construction drawings into a drawing register, and sends every sheet
it isn't sure about to a person, with the reasons and the evidence. Runs locally for free or on
Azure (Document Intelligence, Azure OpenAI, Cosmos DB), keyless.

[![CI](https://github.com/xDarkzx/Revisa/actions/workflows/ci.yml/badge.svg)](https://github.com/xDarkzx/Revisa/actions/workflows/ci.yml)

```
sheet image ─► OCR page ─► find title block ─► OCR enlarged crop ─┬─► rules ──────────┐
               RapidOCR │ Document Intelligence                    └─► language model ─┤
                                                                                       ▼
                    every value must be on the OCR lines it cites ─► accepted │ needs review ─► register
                                                                                                 SQLite │ Cosmos DB
```

## Why

On a construction project, drawings arrive in batches of tens to hundreds of sheets, each
revised many times. A document controller reads every title block (drawing number, title,
revision, date, sheet n of m) and types it into the register. Mistakes mean people build from
superseded drawings, so a wrong value that nobody is told about is worse than no value at all.

## Results

200 real photographed drawings from the Historic American Buildings Survey, one from each of
200 building records, 1843 to the 1990s: printed, hand-lettered, faded, rotated, torn and
negative sheets, plus photographs and book pages that aren't drawings. Each sheet was labelled
field by field, and a blind second reading of a random 20-sheet sample agreed on 93% of values,
with the differences settled from the sheet ([datasets/habs](datasets/habs/README.md#how-the-labels-were-made-and-checked)). Rules and prompts were developed on
93 sheets; the table is the other **107 held-out sheets** ([ADR 0008](docs/adr/0008-held-out-evaluation.md)).

| Run | OCR | Reader | Sheets fully correct | Drawing number read | Title read | Date read | Scale read | Errors sent to review | Accepted with an error |
|---|---|---|---|---|---|---|---|---|---|
| local-rules | rapidocr | rules | 10% | 31% | 21% | 28% | 17% | 85% | 100% |
| local-qwen14b | rapidocr | llm+rules (qwen2.5-coder:14b-instruct-q4_K_M) | 9% | 27% | 23% | 25% | 14% | 94% | 100% |
| azure-rules | azure | rules | 8% | 34% | 16% | 30% | 14% | 96% | 100% |
| rapidocr-gpt41mini | rapidocr | llm+rules (gpt-4.1-mini) | 14% | 36% | 42% | 26% | 18% | 100% | n/a |
| azure-gpt41mini | azure | llm+rules (gpt-4.1-mini) | 12% | 40% | 50% | 32% | 14% | 98% | 100% |

Generated by `revisa report`; per-sheet values, the OCR lines behind each one, and the outcome
of every field are in [evals/results](evals/results). "Read" is the share of values printed on
the sheets that were extracted correctly. "Sheets fully correct" needs all seven fields right,
including scale, revision and sheet numbering.

What the numbers say:

- **The system knows when it doesn't know.** With gpt-4.1-mini, 98% of sheets with any wrong or
  missing value were sent to a person, each with reasons such as "readers disagree on title"
  or "low OCR confidence on date (0.48)". Only 2 of 107 sheets were accepted, and both still
  had an error (a drawing number taken from a "see sheet A-3" note, and a bridge number read as
  the drawing number), so on this archive nothing should be accepted without review.
- **This archive is hard, and automation is low.** Half the titles and 40% of drawing numbers
  are read correctly; dates are 32%, because most are handwritten and neither OCR engine reads
  them reliably. On drawings like these Revisa is a triage tool: it pre-fills the register and
  points a person at the evidence, it doesn't replace them. Modern CAD-printed title blocks
  are a much easier case and are the next dataset to add.
- **The model matters more than the OCR here.** gpt-4.1-mini doubles to triples title accuracy
  over rules alone, with either OCR engine. A 14B local model adds nothing over the rules.
- **Grounding works.** The model can only cite OCR lines; 57 of its values were rejected in the
  Azure run because the words weren't on the lines it cited.
- **Where the losses are.** The title-block locator misses a quarter of the blocks on Azure OCR
  (keywords handwritten or misread), and every field on those sheets is missed. That's the
  largest single improvement available.

## Proof on Azure

[`scripts/azure-proof.sh`](scripts/azure-proof.sh) deployed [`infra/main.bicep`](infra/main.bicep)
once, ran Document Intelligence on every sheet, ran gpt-4.1-mini, loaded the register into
Cosmos DB and read it back, then deleted the resource group: 47 minutes, about US$0.20 of model
tokens, the rest on free tiers. Every service had key authentication disabled; access was by
Entra ID role assignments only. The transcript, resources, register export and what the run
surfaced are in [docs/azure-proof](docs/azure-proof/README.md).

## How it works

- **Locate, then read closely.** The whole page is OCR'd; lines containing title-block words
  (DRAWN, SCALE, SHEET, ...) are clustered to find the block, which is cropped, enlarged and
  OCR'd again to read its small lettering ([ADR 0004](docs/adr/0004-locate-title-block-by-keywords.md)).
- **Two readers.** Pack rules read "label, then the value beside or below it". A language model
  is shown the block's OCR lines with ids and positions and answers with line ids per field.
  Where both read a field and disagree, the sheet goes to review
  ([ADR 0007](docs/adr/0007-two-readers-and-review-routing.md)).
- **Grounding.** A model value is kept only if every word of it is on the lines it cited, so a
  model can choose the wrong text but can't add text that isn't on the drawing
  ([ADR 0003](docs/adr/0003-ocr-first-grounded-extraction.md)).
- **Routing.** A sheet is accepted only with a title block, drawing number, title and date,
  OCR confidence of at least 0.8 behind every value, and no disagreement.
- **Register.** One entry per sheet, keeping the OCR line ids behind each value. Checks across a
  project: superseded revisions, duplicate numbers, missing sheets, conflicting set sizes.
- **Packs.** Everything construction-specific is in
  [`packs/construction.py`](src/revisa/packs/construction.py); medical referrals and supplier
  invoices are specified in [docs/packs.md](docs/packs.md).

More in [docs/design.md](docs/design.md); every significant decision is an
[ADR](docs/adr/README.md).

## Run it

Needs Python 3.11 and [uv](https://docs.astral.sh/uv/); a local model needs [Ollama](https://ollama.com).

```bash
uv sync
uv run revisa dataset-download                 # 200 sheets from Wikimedia Commons, about 300 MB
uv run revisa ocr-pages && uv run revisa ocr-blocks
uv run revisa run my-rules --reader rules      # scores against the labels, writes evals/results/my-rules.json
uv run revisa run my-llm --reader llm+rules --llm ollama --model qwen2.5-coder:14b-instruct-q4_K_M
uv run revisa report evals/results/*.json

uv run revisa register load evals/results/my-llm.json
uv run revisa register check                   # superseded, duplicate, missing sheets
uv run revisa register review                  # the review queue with reasons
uv run revisa register latest A-19
```

On Azure, `scripts/azure-proof.sh` does all of the above with `--engine azure`, `--llm azure`
and `--store cosmos` after deploying, then tears down.

## Engineering

| Gate | Where |
|---|---|
| Ruff, including security (bandit) and pylint rule sets | pre-commit and CI |
| mypy `--strict` over the package and scripts | pre-commit and CI |
| pytest, 90 tests, coverage at least 85% (93% now); no test touches the network or a model | CI |
| pip-audit on the locked dependencies; gitleaks over the full history | CI |
| Bicep lint and build; shellcheck | CI |
| Conventional Commits, enforced by a commit-msg hook | pre-commit |
| `main` protected: pull request, all checks green, squash merge, linear history | GitHub ruleset |

Evaluation data and results are versioned with the code that produced them; every result file
records its commit. Labels change only to match the sheet, with each change logged.

```
src/revisa/
  ocr.py, locate.py, blocks.py   OCR engines, title-block location, enlarged re-read
  extract.py, llm.py             grounded values; the language-model reader
  pipeline.py                    routing and two-reader cross-check
  evaluate.py, runs.py           scoring, dev/test split, batch runs, reports
  register.py                    SQLite and Cosmos DB registers, set checks
  packs/construction.py          everything specific to construction drawings
infra/main.bicep                 Document Intelligence, Azure OpenAI, Cosmos DB, role assignments
scripts/azure-proof.sh           the one-time deploy, run and teardown
datasets/habs/                   manifest and labels
evals/results/                   every scored run
docs/                            design, ADRs, packs, Azure proof
```
